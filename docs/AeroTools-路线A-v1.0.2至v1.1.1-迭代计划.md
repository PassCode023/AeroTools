## 1. 目标与边界

路线 A 先完成数据可信与发布硬化，再增加离线单位换算，最后增强机场搜索与详情，目标版本为 v1.1.1。

本路线明确延后以下内容：

- 在线更新服务、更新清单 SHA-256 校验和托管部署在 v1.1.1 完成后单独规划。
- `DB_UPDATE_BASE_URL` 保持为空，在线更新入口保持隐藏。
- 未经明确授权，不提交应用商店审核、不创建 Git 标签、不上传或公开发布正式版本。
- iOS 候选包的签名与真机安装依赖 Apple 开发者账号及证书。2026-09-15 验收口径修订后，iOS 仅要求 APP 资源构建（编译）通过，不再要求签名、安装与真机验收；Apple 开发者账号不再构成路线阻塞。
- 首页文案继续保留“时间与航路，尽在掌握”。

## 3. 信息来源与获取合规

### 3.1 总体规则

- 所有信息必须来自无需登录即可查看或直接下载的公开页面。
- 允许人工浏览公开页面、下载发布方明确提供的单个 CSV、JSON 或 PDF，以及安装具有明确开源许可证的 npm 包。
- 禁止网页爬虫、批量 HTML 抓取、无头浏览器采集、模拟登录、使用私人 Cookie 或 API Key、绕过验证码或限流、调用未公开接口。
- 应用、构建脚本和 CI 均不得自动访问外部数据网站；构建和测试只能读取已进入仓库并完成来源登记的本地数据。
- 每个实际使用的数据来源必须记录：URL、提供方、访问日期、使用字段、获取方式、许可证或使用边界、原文件 SHA-256。
- “公开可访问”不等于“允许复制或再分发”。许可证不明确的页面只用于人工事实核对和引用，不批量复制、缓存或再分发页面内容。
- 无法从许可清晰的来源确认的代码、英文名、坐标、时区或海拔必须保持为空，不得猜测或使用伪造零值。

### 3.2 允许使用的来源

| 来源 | 用途 | 许可/边界 | 获取方式 |
|---|---|---|---|
| [airportsdata](https://github.com/mborsetti/airportsdata) | 机场代码、英文名、坐标、时区、海拔等基础字段 | MIT | 下载发布方公开 CSV 原文件并登记 SHA-256。注：该数据集仅提供 PyPI 包（Python）与原始 CSV，无 npm 包，本项目不引入 Python 依赖 |
| [OurAirports](https://github.com/davidmegginson/ourairports-data) | 基础字段交叉核对与缺失项补充 | Unlicense | 下载发布方公开 CSV；登记 SHA-256 |
| [pinyin-pro](https://github.com/zh-lx/pinyin-pro) | 构建全拼和拼音首字母 | MIT；仅作构建工具，不进入客户端运行包 | 固定安装 `pinyin-pro@3.29.4` |
| [中国民航局运输机场名录](https://www.caac.gov.cn/GYMH/MHGK/MYJC/) | 境内运输机场数量、正式中文名及更名事实的人工核对 | 仅人工事实核对与引用，不复制网页或编写提取程序 | 人工逐页浏览，无需登录 |
| [BIPM SI Brochure](https://www.bipm.org/en/publications/si-brochure) | 国际单位制定义与单位常数依据 | 按发布方公开使用条件引用 | 人工查阅公开页面或 PDF |
| [NIST SP 811 Appendix B](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors) | 英制与 SI 换算常数交叉核对 | 按发布方公开使用条件引用 | 人工查阅公开页面或文件 |

### 3.3 来源登记与审计产物

v1.0.2 必须新增并维护以下记录：

- 数据来源清单及每个来源的实际使用字段。
- 第三方许可证清单和许可证原文/链接。
- 下载原文件的文件名、访问日期和 SHA-256。
- 民航局运输机场名录人工逐页核对记录。
- 字段冲突、名称变更、旧名、缺失字段及最终处理结论。

任何来源或字段无法满足上述记录要求时，不得进入可再分发的客户端数据。

上游发布文件（两个开源数据集的原始 CSV，合计数 MB）不进入 git 仓库；来源登记表记录其 URL、文件名、访问日期和 SHA-256。进入仓库的是含 `caacRef` 的转换后源数据（`airport-data/data-*.json` 及后续核对产物），其上游来源通过登记的哈希复现验证。第 3.1 节“构建和测试只能读取已进入仓库并完成来源登记的本地数据”即指该转换后源数据。

## 4. v1.0.2：数据可信与发布硬化

### 4.1 数据来源、许可与人工核对

1. 增加数据来源、第三方许可和人工核对记录。
2. 人工逐页核对截至 `2025-12-31` 的 270 个境内运输机场。
3. 每条被纳入 270 个覆盖门禁的源记录增加源数据专用 `caacRef`。
4. 正式更名后更新中文名，旧名写入 `aliases`。
5. 港澳台机场和非运输机场可以保留在通用机场库中，但不计入 270 个境内运输机场门禁。
6. 补齐全部经人工确认真正缺失的境内运输机场。
7. 民航局页面只用于人工核对中文名、数量及更名等事实；不得编写或保存网页提取脚本。

### 4.2 构建门禁

机场数据构建必须在本地、离线且可重复地完成，并满足：

- `caacRef` 恰好 270 条。
- 纳入门禁的机场中文名唯一。
- `coverage.matched = coverage.expected = 270`。
- 人工核对记录的分页、数量与总数一致。
- 无法确认的 IATA、ICAO、英文名、城市、坐标、时区或海拔保持为空。
- `caacRef` 仅存在于源数据和审计记录中，不进入客户端机场 JSON。
- 构建脚本、测试和 CI 不访问任何外部数据网站。
- 既有 `airport-data/build.js` 的 `cnCount >= 240`（`country=中国`，含港澳台 10 条）与 `total >= 500` 数量门禁，以及 `app/tests/airportsData.test.ts` 中的同款断言，在本版本改写为上述 270 精确门禁。改写断言不视为“减少既有 89 项测试”。

### 4.3 数据契约

- `Airport` 只强制要求中文名和国家。
- IATA、ICAO、英文名、城市、时区等字符串字段允许为空。
- 纬度、经度和海拔改为可选字段。
- 旧名通过 `aliases` 表达。
- 数据来源由单一文本字段改为结构化 `sources`。
- 数据清单增加 `verifiedAt` 和 `coverage`。
- 客户端数据不包含内部核对字段 `caacRef`。
- 契约放宽必须同步覆盖在线更新校验：`app/src/utils/updater.ts` 的 `validateAirportData` 与内置构建契约保持同一数据契约，并同步更新 `app/tests/updaterValidate.test.ts`、`app/tests/dbUpdate.test.ts`。

### 4.4 页面和降级展示

- 设置页展示 airportsdata、OurAirports、中国民航局三个来源及各自用途。
- 设置页显示“境内运输机场 270/270（截至 2025-12-31）”。
- 所有缺失字符串、坐标、时区或海拔统一显示 `—` 或“暂无可靠数据”。
- 禁止把缺失的坐标、时区或海拔显示为 `0`。
- 首页继续显示“时间与航路，尽在掌握”。
- 数量口径同步拆分：README 与设置页的“中国 247（含港澳台 10 条）”改为“内地运输机场 270/270＋通用库另含港澳台 10 条”口径，收录总数（现 519）随补齐结果同步更新。
- 字段完整率（completeness）继续仅在数据清单中维护，不上应用界面；来源展示仍仅限设置页。

## 5. v1.1.0：离线单位换算

### 5.1 功能范围

新增六组双向离线换算：

| 分类 | 换算关系 |
|---|---|
| 长度 | `1 ft = 0.3048 m` |
| 航程 | `1 NM = 1.852 km` |
| 速度 | `1 kt = 1.852 km/h` |
| 气压 | `1 inHg = 33.8638866667 hPa` |
| 质量 | `1 lb = 0.45359237 kg` |
| 温度 | `°F = °C × 9/5 + 32` |

### 5.2 交互和输入规则

- 页面使用“分类切换＋双输入框”。
- 任一侧输入有效值时立即更新另一侧。
- 除温度外拒绝负数。
- 空值、未完成小数和无效值不产生结果。
- 输入无效时不得复用或误显示上一次计算结果。

### 5.3 显示精度

| 分类 | 精度 |
|---|---|
| ft / m | 最多 2 位小数 |
| lb / kg | 最多 2 位小数 |
| NM / km | 最多 3 位小数 |
| kt / km/h | 最多 3 位小数 |
| hPa | 1 位小数 |
| inHg | 2 位小数 |
| ℃ / ℉ | 1 位小数 |

### 5.4 范围限制

- 首页增加“单位换算”入口。
- 所有换算均在本地完成，不访问网络。
- 本版本不增加历史记录、收藏、自定义单位或持久化。

## 6. v1.1.1：机场搜索与详情增强

### 6.1 构建期拼音数据

- 在机场数据构建环境固定 `pinyin-pro@3.29.4`。
- 构建中文名、城市和别名的全拼与拼音首字母搜索字段。
- 拼音生成只发生在构建期。
- 客户端运行依赖和最终微信产物不得包含拼音库代码。

### 6.2 查询归一化

查询统一处理：

- 大小写；
- 全角和半角字符；
- 空格；
- 连字符；
- 点号；
- 拉丁重音。

本版本不实现模糊拼写纠错。

### 6.3 排序规则

搜索结果按以下优先级排序：

1. IATA 或 ICAO 精确匹配。
2. IATA 或 ICAO 前缀匹配。
3. 中文名、城市、别名、英文或拼音精确匹配。
4. 文本前缀匹配。
5. 包含匹配。
6. 同分时保持数据库原始顺序。

搜索结果最多返回 50 条。

### 6.4 机场详情

- 海拔同时显示 `ft / m`。
- 坐标同时显示十进制度和航空度分格式。
- 时区显示 IANA 名称及当前日期对应的 `UTC±HH:MM`。
- 不支持或非法的时区显示“当前偏移不可用”。
- 显示资料截至日期。
- 显示夏令时提示；只展示当前偏移，不支持任意日期偏移查询。
- 缺失字段继续统一显示 `—` 或“暂无可靠数据”。
- 时区偏移与夏令时提示不依赖运行时 `Intl` 时区支持（微信小程序 iOS 端 JavaScriptCore 支持不完整）：采用构建期生成的时区偏移查表，并在微信真机验证。

## 7. 全局实施门禁

1. 每个版本遵循测试驱动：先写失败测试并保存失败证据，再实现最小正确代码。
2. 前一版本未完成自动化测试和微信真机验收，不开始下一版本。
3. README、CHANGELOG、版本迭代记录和 `.ai/` 状态按版本独立维护。
4. 构建、签名包、安装、审核和公开发布是五个独立状态，必须分别记录。
5. 未经明确授权，不得提交审核、打标签、推送发布分支或公开发布。
6. 任何实现不得引入网页爬虫、批量 HTML 抓取、无头浏览器采集、模拟登录或未公开接口。
7. 公开可访问不代表具有开源许可证；许可证不明确的页面只用于人工事实核对和引用。
8. v1.1.1 完成后，再单独规划在线更新服务、清单 SHA-256 与托管部署。
