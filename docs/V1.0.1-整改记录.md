## 1. P0-1 时间计算：首次输入后的纠错与清空

**修复内容**

- 新增纯函数状态机 `app/src/utils/calcInput.ts`（`pressKey` 返回新状态 + 事件），页面只消费事件（计算链/历史副作用留在 `time-calc.vue`）。
- **退格取回编辑**：已提交首个操作数且未进入运算时，退格把该值还原为 4 位数字并删除末位，回到可编辑状态；计算结果（可能跨日/负值/超 4 位）一律不取回，避免语义错乱。
- **C 键整单重置**：任意状态（含已提交、运算中间态、多步链之后）点击 `C` 直接开始一笔新计算。
- 修正提示语：`time-calc.vue` 中"或清空重新开始"原来指向不存在的入口，现改为"请选择 ＋ 或 － 继续运算，或按 ⌫ 修改、C 清空重来"，与实际可用操作一致。
- 数字键盘 14 键补齐 `aria-label`（退格删除末位/清空重算/确认输入/加/减）。

**测试**：`tests/calcInput.test.ts` 17 项（含报告要求的"首次输入后纠错""首次输入后清空"用例），并回归保护既有行为（自动提交、类型锁定、incomplete/invalidClock 拒绝、badOp 防御分支）。

**H5 实测**：输入 `1425` → 提交 `14:25`；退格 → 回到 `14:2_` 可编辑；补 `3` → 重新提交 `14:23`；`C` → 回到初始；`2330 + 0215` → `01:45 次日 / 累计 25:45`；`C` 清空。全部通过。

## 3. P0-3 更新链路：隐藏入口 + 原子写入 + 结构校验

**修复内容**

- `DB_UPDATE_BASE_URL` 为空时：设置页不再渲染"检查更新"按钮、状态栏位与下载说明（整个更新状态栏随配置隐藏）；README 同步修正"支持在线更新"表述。
- `app/src/utils/db.ts` 重写为**原子写入协议**：新库写入带版本号的分块键（`at:db:chunk:<version>:<i>`）→ 全部成功后写 meta（唯一提交点）→ 按写入前快照的旧 meta 清理旧库分块（含 v1 固定键迁移兼容）。任一步失败即回滚新键，旧库 meta/分块未被触碰——修复了评审指出的"同键覆盖、中途失败丢库"与注释失实问题。
- `app/src/utils/updater.ts` 新增 `validateAirportData` 逐字段结构校验（数组/条数/必填/坐标/代码），接入下载流程；两处失实注释已修正。
- **遗留**：SHA-256 摘要校验依赖真实更新服务联调（需服务端 manifest 同步产出摘要），本次延后，已在 README 已知边界注明。

**测试**：`tests/dbUpdate.test.ts` 7 项（成功写入、分块中途失败保留旧库且回滚半成品、meta 失败回滚、块数收缩清理旧块、v1 固定键迁移、clearLocalDb 回退、溯源字段透传）；`tests/updaterValidate.test.ts` 6 项。

**H5 实测**：设置页无任何更新入口，状态行如实显示。
