# AeroTools 民航工具箱 — V1 设计文档

日期：2026-09-13
依据：《民航工具 APP V1 终端用户需求调查》20260913-FRRBO（已确认条件见问卷 YAML）
状态：已与用户确认技术选型与数据来源

## 1. 目标与边界

一套 uni-app (Vue 3 + TypeScript) 代码，产出：

- Android APP / iOS APP（HBuilderX 云打包）
- 微信小程序
- H5（开发预览与演示用）

核心功能完全离线可用；机场数据库支持在线更新（静态文件托管）。

**V1 明确不做**（问卷结论）：UTC/Zulu 转换、秒精度、最近查询、收藏机场、账号/云同步。
**V1.1 变更（用户追加需求）**：界面组件参考 uiverse/galaxy 风格语言（渐变、大圆角、柔和阴影、胶囊按钮），并增加**浅色/深色双主题**（覆盖问卷"深色模式不重要"的结论，以用户最新要求为准）。

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | uni-app CLI (vite-ts) | 一套代码 → APP/小程序/H5，国内生态成熟 |
| UI | 自写轻量组件 + SCSS | 页面少，避免第三方 UI 库多端兼容坑 |
| 状态 | Vue 3 composable，无 Pinia | 规模小，YAGNI |
| 存储 | `uni.*Storage` 封装 + 分块 | 小程序单 key 1MB 限制 |
| 测试 | vitest（纯逻辑 TDD） | 时间运算/搜索是安全路径，必须先测后码 |

## 3. 页面与导航

无 tabBar（问卷：首页两个大按钮）。

1. `home` 首页：标题 + 时间计算 / 机场查询 两大按钮 + 数据库版本角标 + 设置入口
2. `time-calc` 时间计算器
3. `airport-search` 机场查询
4. `settings` 设置：数据库版本、检查更新、关于

## 4. 时间计算器设计

### 4.1 数据模型

- 一切时间以「分钟整数」计算。
- **时刻 (clock)**：0–1439（显示 HH:MM）；**时长 (duration)**：任意整数分钟，可 >24h、可为负。
- 输入：连续数字自动格式化——数字键盘只录数字，缓冲区最多 4 位（小时可 >23 时缓冲 5–6 位），按 `HH:MM` 呈现；时刻输入校验 0–23 时、0–59 分。

### 4.2 运算

| 左值 | 运算符 | 右值 | 结果语义 |
|---|---|---|---|
| 时刻 | + | 时长 | 时刻（可跨日） |
| 时刻 | − | 时长 | 时刻（可跨到前日） |
| 时刻 | − | 时刻 | 时长（可为负） |
| 时长 | + | 时长 | 时长 |
| 时长 | − | 时长 | 时长 |

多步：上一步结果作为下一步左值；结果类型决定下一步可用运算符组合（时刻只能 ±时长；时长任意）。

### 4.3 显示规则（问卷 Q7/Q8：双解读同显）

- 结果为时长：显示 `H:MM`（H 可 >23）；若为负，同显「数学结果」与「+24h 跨日读数」；若 >24h，同显「累计」与「模 24 时刻」。
- 结果为时刻：显示当日 HH:MM；跨午夜时同显「累计时长」与「次日/前日时刻」并标注「次日/前日」。

### 4.4 历史记录

本地最近 50 条（表达式 + 双格式结果 + 时间戳），可查看、单条删除、清空。入口在计算器页，非必须功能，实现保持轻量。

## 5. 机场查询设计

- 搜索字段：IATA、ICAO（不区分大小写，前缀优先、包含其次）、中文机场名、中文城市名（包含匹配）。
- 实时匹配：输入防抖 ~120ms，上限渲染 50 条。
- 列表项：IATA/ICAO 徽标 + 中文名 + 城市/国家；点击展开详情：坐标、时区、海拔、英文全名。
- 无最近查询、无收藏。

## 6. 机场数据库设计

### 6.1 数据集

- 中国全部运输机场（约 260 家）+ 全球主要机场，合计目标 1000–1300 条。
- 字段：`iata, icao, nameZh, nameEn, cityZh, cityEn, country, lat, lng, tz, elevM`（`iata` 允许空字符串——少数只有 ICAO 的机场）。

### 6.2 数据管道 `airport-data/build.js`（纯 Node，零依赖）

合并 `data-cn.json` + `data-global.json` → 校验（IATA/ICAO 唯一、必填、坐标范围、中国机场 ≥250 sanity）→ 产出：

- `app/src/static/airports.json`（内置离线包）
- `airport-data/dist/manifest.json` + `airports-<version>.json`（静态托管部署包）

### 6.3 在线更新流程（问卷 Q20/Q21：提示确认 + 任意网络）

1. 触发：APP 启动静默检查 + 设置页手动「检查更新」。
2. `GET {BASE_URL}/manifest.json`（几 KB）→ 比较版本号（语义化 `YYYY.M.N`）。
3. 有新版 → 弹窗展示版本/条数/时间 → 用户确认 → 下载全量 JSON（Wi-Fi/移动网络均可）。
4. 解析校验（结构 + 条数与 manifest 一致）→ **分块**写入本地存储（每块 ~400 条，规避小程序 1MB 单 key 限制）→ 更新本地版本号。
5. 任一步失败：保留旧库，提示失败原因；未部署服务端（URL 为空/404）时静默跳过。
6. 加载策略：本地存储版本 ≥ 内置版本 → 用存储库；否则用内置包。

更新地址集中在 `app/src/config.ts`，部署后填入即可生效。

## 7. 错误处理原则

- 数据库下载/写入失败不阻断使用（回退旧库）；解析失败丢弃新数据。
- 时间输入非法（时刻 >23:59）在键盘层拦截，不产生错误态。
- 搜索空结果有空状态提示。

## 8. 测试策略

- `timeMath.ts`：vitest 单测 20+ 用例（跨午夜加/减、负值双解读、>23h 时长、多步链、格式化、非法输入）。
- `airportSearch.ts`：vitest 单测（IATA/ICAO/中文名/城市、大小写、空查询、排序优先级）。
- `build.js` 校验步骤在构建时强制执行，失败即构建失败。
- UI 手工验证：H5 浏览器实测 + 微信开发者工具预览。

## 9. 交付边界

- APK/IPA 打包需用户在 HBuilderX 完成（iOS 需苹果开发者账号）；交付源码 + 步骤文档。
- 小程序发布需用户注册账号并填 appid。
- 静态托管：`airport-data/dist/` 两文件上传任意静态托管（OSS/COS/自有服务器），把 URL 填入 `config.ts`。
